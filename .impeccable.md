# Impeccable Design Context — ChamelShot

## Design Context

### Users
Keyboard-driven tiling window manager users (niri first, then Sway/Hyprland/river).
They live in the terminal, bind Print to capture, and expect tools to be fast,
keyboard-first, and lightweight. No mouse-hunting, no fluff, no learning curve —
the tool should disappear into their workflow. Interaction is mostly: hotkey →
capture → save/annotate → back to work in seconds.

### Brand Personality
Fast, dense, unimpressed. The UI is a utility, not a showpiece: tight spacing,
short labels, zero decoration that doesn't carry information. It should feel
like a good CLI tool wearing a GUI — honest, immediate, and quietly confident.
No marketing copy, no empty states that lecture, no celebratory animations.

### Aesthetic Direction
Dark-first desktop tool rooted in the existing launcher palette (#161617 surface,
#d4d4d8 text, zinc-tinted neutrals). Theme should follow the system/compositor
appearance where possible (light and dark variants of the same design, never a
re-skin). Reference the sensibility of grim/slurp and Sway's own tooling:
minimal, monospaced-friendly, dense. Anti-reference: GNOME's screenshot flow —
flat generic dialogs, oversized chrome, wizard-like steps. Never that.

### Design Principles
1. **Keyboard-first everything.** Every menu item, picker entry, and dialog
   control reachable or accelerateable via keys; no action requires a mouse.
2. **Dense, not cluttered.** Tight spacing, small but legible type, single
   focused action per surface. Prefer compact native widgets over custom chrome.
3. **System-respectful.** Follow the compositor/system theme (light/dark),
   use native dialogs where they exist, honor existing shortcuts/config
   conventions.
4. **Zero ceremony.** No splash screens, no confirmation dialogs for normal
   actions, no decorative elements. The tool gets out of the way.
